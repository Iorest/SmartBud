# 记账口径：一条记录到底算进哪里

这份表是各子功能共用的"会计准则"。改任何一处统计前先看这里，否则很容易出现
「账户余额对得上、统计对不上」或者「昨天小计和本月合计互相矛盾」。

## 一行的身份

`TransactionModel` 只有三种特殊身份，其余都是普通收支：

| 身份 | 字段 | 记账含义 |
|---|---|---|
| 普通支出 | `income = false` | 真的花掉了 |
| 普通收入 | `income = true` | 真的赚到了 |
| 报销支出 | `reimbursable = true`（`reimbursedAt` 表示已回款） | 垫付，钱会回来 |
| 报销回款 | `income = true` + `reimbursementOf = <报销支出的 id>` | 公司/同事把钱还回来 |
| 余额调整 | `adjustment = true` | 只是把账面数字改对，不是消费 |

**报销是一对两行，不能只有一半。** 只标记「已报销」而不记账，账户余额会永远少那笔钱；
只记一笔收入而不标记，收入会凭空多出来。所以核销时由 `ReimbursementLedger` 自动写入
回款行（金额、账户、基准币金额都与原支出一致），撤销核销时把这一行删掉。

一笔转账不是交易，单独存在 `TransferModel`：钱从 A 到 B，属于账户间移动。

## 影响面

| 用途 | 普通支出 | 普通收入 | 报销支出 | 报销回款 | 余额调整 | 转账 |
|---|---|---|---|---|---|---|
| 账户余额 | 计入 | 计入 | **计入**（钱确实出去了） | **计入**（钱确实回来了） | **计入** | 转出扣 `amount + fee`，转入加 `receivedAmount` |
| 支出统计 / 分类占比 / 柱状图 | 计入 | — | 不计入 | 不计入 | 不计入 | 不计入 |
| 收入统计 | — | 计入 | — | **不计入** | 不计入 | — |
| 净收入（收入 − 支出） | 计入 | 计入 | 不计入 | 不计入 | 不计入 | 不计入 |
| 预算剩余 | 计入 | — | 不计入 | 不计入 | 不计入 | 不计入 |
| 流水日小计 | 计入 | 计入 | 0 | 0 | 0 | 0 |
| 「待报销」卡片 | — | — | 未回款的计入 | — | — | — |
| AI 账单分析 | 计入 `totalSpent` | 计入 `totalIncome` | 单独字段 `pendingReimbursement` | 不计入 | 不计入 | 不计入 |
| 小组件 | 同 App | 同 App | 不计入 | 不计入 | 不计入 | 不计入 |

一对报销的净效果永远是 0：账户 −88 再 +88，支出和收入都不变，日小计也不变
（流水里两行加起来正好抵消）。

实现上只有三个判定，全部在 `TransactionModel` 的扩展里：

```swift
countsAsSpend   // !income && !adjustment && !reimbursable
countsAsIncome  // income && !adjustment && !isReimbursementIncome
signedBaseAmount // 收入 +base，支出 -base，其余 0
```

**所有统计代码都必须走这三个判定**，不要再手写 `!$0.income` —— 那正是
「报销混进支出」「余额调整拉高收入」的来源。

报销的一对行由 `Services/ReimbursementLedger.swift` 维护：核销写入回款、撤销删除回款、
编辑任一半同步另一半、删除原支出连带删除回款、删除回款把原支出放回「待报销」。
SQL 侧的 `#Predicate` 同样不能表达 `reimbursementOf != nil` 之外的组合，所以那里直接
取所有回款行再在内存里比较 id。

例外只有一处：SwiftData 的 `#Predicate` 不能调用计算属性，预算明细的查询里
必须把三个标记写全：

```swift
!$0.income && !$0.adjustment && !$0.reimbursable
```

改动其中任何一个标记时，记得同步 `FilteredBudgetViews` 里的谓词。

## 金额的两个版本

- `amount`：账户币种下的原值。跨币种账户里它就是外币金额。
- `baseAmount`：记账当时按汇率折算的基准货币金额，**冻结**。

所有跨账户、跨期的合计一律用 `wrappedBaseAmount`（取 `baseAmount`，旧数据退回 `amount`），
这样改汇率不会让历史统计漂移。

## 转账手续费

`fee` 记在转出账户的币种上：转出方实际损失 `amount + fee`，转入方只收到
`receivedAmount`。手续费**不进支出统计**（转账是账户间移动），但会体现在账户余额里；
流水行和账户页的转账条目都会显示 `¥100 + ¥2.50`，避免"余额少了但流水看不出来"。

## 跨功能约定

- **删除**：删账户 → 交易保留、清空归属，相关转账一并删除；删分类 → 交易保留、
  清空分类与备注中的分类名副本，关联预算一并删除。
- **归档**：不进默认账户列表、不计总资产、不能作为新记账的默认账户或转账端点，
  但历史交易、转账、报表照常解析。
- **隐藏**：仍在列表里（半透明），只是不计总资产。
- **撤销删除**：`TransactionSnapshot` 必须保存编辑器能写的所有字段
  （账户、baseAmount、折扣、报销、调整）—— 少一个字段，撤销就会悄悄改掉余额。
- **导入**：按 id 合并；导入后要刷新账户、分类、统计、小组件四处缓存。
