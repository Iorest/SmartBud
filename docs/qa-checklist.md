# 交互验收清单：哪些靠机器，哪些只能靠人

自动化不能覆盖全部交互。这份清单把两者分开：能断言的进 XCUITest，需要"感知"的留给人工，
每次发版前按表跑一遍。

## 分工原则

| 类型 | 归属 | 原因 |
|---|---|---|
| 点击、输入、页面跳转、数据结果 | XCUITest（见下方 34 条用例） | 可断言、可重复 |
| 触感、动画手感、语音朗读、真机键盘、多设备同步 | 人工 | 模拟器无法真实感知或需要第二台设备 |
| 对比度、命中区、标签缺失 | `performAccessibilityAudit` + 人工复核 | 机器能报大部分，语义仍要人判断 |

## 自动化覆盖

TELE-36/37/38 分三批覆盖交互流程（记账、编辑、删除撤销、转账、预算、账户、导入导出、搜索筛选、深链、
锁定、Pro 闸门、智能记账、设置、布局），每条至少一个断言落在数据或文案上。
当前落到 CI 的共 34 条：TELE-24 的 8 条 smoke（`ui-test` 的 smoke 分片），以及 TELE-36 的
A1–A10、TELE-37 的 B1–B6 与 TELE-38 的 10 条 C 用例共 26 条 E2E（按实测耗时分五个分片并行，见 `engineering.md`）。
新增用例要同时把它加进 `.github/workflows/ci.yml` 对应分片的
`tests` 列表和 smoke 的 skip 列表，否则要么被 smoke 抢跑、要么没进任何分片（「全绿但一条没跑」）。

覆盖不到、也不打算自动化的：触感、动画手感、语音识别本身、CloudKit 双设备时序。

## 回归频率

| 时机 | 跑什么 |
|---|---|
| 每个 PR | 单元测试 + 解析指标门槛 + `ui-test` 的六个分片（8 条 smoke + 26 条 E2E） |
| 每天 | 全量 UI 流程——尚无定时任务；34 条用例已在每个 PR 的六个分片里跑完，也可手动 `workflow_dispatch` 触发 |
| 每次发版 | 人工清单 M1–M14 + 真机冒烟 |
| 改口径/迁移 | 额外跑导入导出往返与统计对拍 |

## 缺陷分级

| 级别 | 定义 | 处理 |
|---|---|---|
| P0 | 金额、余额、统计、导入导出结果错误 | 阻塞发版，当天修 |
| P1 | 流程中断、崩溃、锁失效、数据丢失 | 阻塞发版 |
| P2 | 文案、间距、动画不顺 | 进下个迭代 |
| P3 | 美观偏好 | 记录，不排期 |
